# 封面工作台保存配置与发布同源生成

## 改了什么

封面工作台(公众号封面生成工作台弹窗)新增「💾 保存配置」主按钮,一键把 **封面主题 + 比例 + 6 个文案字段**(主标题/副标题/标签/徽章/期号/作者)作为快照写入 `localStorage`(`md2wx_cover_workbench`),由新纯逻辑模块 `web/src/core/coverWorkbench.js` 承担读写与校验。

语义是**保存才生效**:

- 点保存前,工作台里的一切修改只是预览;保存按钮带黄色未保存圆点,表单偏离已保存基线时亮起;
- 发布推送导出、发布缩略图、正文顶部封面卡三处消费点,统一经 `app.js#getSavedCoverConfig()` 读取快照渲染——修复了此前「工作台里选的主题与比例,推送时从不生效(写死编辑器主题 + 2.35:1)」的老 bug;
- 重开工作台恢复上次保存的配置,刷新页面不再丢失;「同步正文」仍是预览层操作,不自动保存;
- 保存「双图合拼(dual)」时,推送与缩略图回落 2.35:1 导出(双拼是手动裁剪素材,直推草稿箱会变形),发布工坊状态栏明示「双拼配置,推送按 2.35:1 导出」;工作台内「下载高清 PNG」仍输出双拼原图。

正文顶部封面走 `parser.js` 新增的可选渲染项 `coverThemeId`:正文排版跟随编辑器主题,封面卡片跟随保存的封面主题,两者解耦。

## 兼容红线怎么验证的

从未点过保存(无 `md2wx_cover_workbench` 键)时,行为必须与线上现状逐一一致。逐条核对:

- 发布缩略图:无快照走保留的历史渲染分支,输出字符串与改造前**逐字节一致**(浏览器实测 `byteIdentical: true`);
- 推送导出:无快照回落 `(currentThemeId, 'banner', currentCoverMeta || {})`,与原调用参数完全相同;
- 正文顶部封面:`coverThemeId` 不传时 `parser.js` 回落 `themeName`,其它调用方零影响;
- 工作台打开:无快照维持「编辑器主题 + 正文提取 + banner」现状。

快照损坏(非法 JSON/缺字段/ratio 非法)读取一律返回 null 回落现状,绝不中断渲染或推送;保存遇到存储不可用/quota 超限会 toast 报错,不允许静默假成功。

测试:新增 `coverWorkbench.test.mjs` 8 用例(写读往返/白名单/trim/非法输入容错/dual 回落),Node 全套 129 项、Python 44 项全绿,vite 构建通过。

## 用户冒烟清单

1. 工作台改主题+比例+文案 → 保存按钮出现黄点 → 点「💾 保存配置」→ toast 成功、黄点消失;
2. 保存 square 后再改动但不保存 → 发布工坊缩略图仍是 square 形态,推送导出为 square;
3. 保存 dual → 缩略图/推送回落 banner 且状态栏有提示;工作台内「下载高清 PNG」仍是双拼原图;
4. 清空 localStorage 的 `md2wx_cover_workbench` → 推送、缩略图、正文顶部封面与线上现状一致;
5. 保存某封面主题(如 dark-night)后切换编辑器主题 → 正文顶部封面仍为 dark-night,正文排版跟随编辑器主题。
